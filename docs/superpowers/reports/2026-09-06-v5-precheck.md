### 3.3 `previewMarketOnly` — the answer to the dispatch's direct question

**It does not exist in dev.** `grep -rn "previewMarketOnly" web/src` → **0 hits**.
It is invented by the proposal's `ChartTabs.tsx` change (hunks 1–2 add it to
`ChartTabsProps` and the destructure).

What it does, in the proposal's ChartTabs:

```
-  const [activeTab, setActiveTab] = useState<ChartTab>('equity')
+  const [activeTab, setActiveTab] = useState<ChartTab>(previewMarketOnly ? 'kline' : 'equity')
...
+          {!previewMarketOnly && <>          // hides the Equity/K-line switcher
+          </>}
+          {previewMarketOnly && <strong className="preview-chart-label">Market Chart</strong>}
```

**So "strip the prop" is NOT a safe simplification, and this is the single most
important result in Section E.** On dev today:

```
web/src/components/charts/ChartTabs.tsx:148   const [activeTab, setActiveTab] = useState<ChartTab>('equity')
web/src/components/charts/ChartTabs.tsx:473     <EquityChart traderId={traderId} embedded isFutures={isFutures} />
```

`EquityChart`'s only production call site is **inside ChartTabs**, behind the
equity tab, and the equity tab is the **default**. The v5 page adds a *second*,
top-level `<EquityChart>`. Therefore:

- **Ship `TraderDashboardPage.tsx` alone, prop included** → `previewMarketOnly`
  is not a member of `ChartTabsProps` on dev → **`tsc` build failure**. Loud, not
  silent. `cd web && npm run build` catches it.
- **Ship it alone with the prop stripped** → ChartTabs still opens on **equity**,
  so the owner sees the equity curve in the chart slot *and* a second equity chart
  in the new section. **Two equity charts, no market chart until you click.**
  That is the precise opposite of the packet's stated decision ("Market Chart and
  Account Equity appear together").

The v5 layout intent **requires** a ChartTabs change. The honest production form
is a real prop (`defaultTab`, or `marketOnly`) rather than one named `preview*`.
This makes ChartTabs a **mandatory** part of the change, not an optional extra —
which the dispatch's one-file premise would have hidden.

Second-order: the top-level `<EquityChart>` does **not** pass `embedded`, which
defaults to `false` (`EquityChart.tsx:43`). At `embedded=false` the component
renders its own `binance-card` chrome and its own title header
(`EquityChart.tsx:90, :91, :108, :135, :136, :256, :262`), while every sibling
panel on this page uses `nofx-glass`. The new card will not match its neighbours.

### 3.5 Grid-order regression (the one a reviewer would miss)

The four children of the grid container end up in this DOM order:

1. left column (chart + positions)
2. `<section class="preview-equity">` (new)
3. right column (`id="activity"`)
4. `<section id="planner">` (new)

That reads correctly **only** because hunk 3 changed the container to
`grid-cols-1`. If a later reviewer restores `lg:grid-cols-2` — the natural
instinct, since the page is wide — the layout silently becomes:

```
row 1:  [ chart+positions ]  [ equity   ]
row 2:  [ activity        ]  [ planner  ]
```

…which is a plausible-looking layout that nobody designed. **Test that would catch
it:** none exists. This is the strongest argument for the pin proposed in §6.
